# Trwały feedback — live acceptance

Poniższe zasady dotyczą runów live acceptance dla AART, chyba że użytkownik wyraźnie postanowi inaczej.

1. Notuj findingi jako residua i nie naprawiaj ich w trakcie runu — analiza powstaje ze zbioru wyników na końcu. Wyjątek: problem blokuje dalszy run i nie ma obejścia.
2. Credentiale wpisuje człowiek, nigdy agent. Agent może przygotować i wyjaśnić komendę, po czym przekazuje wykonanie człowiekowi.
3. Curses prowadzi człowiek; agent prowadzi wyłącznie tekstowy front-end.
4. Instalatory MCP są wykonywane na końcu runu i prowadzi je człowiek.
5. Postęp jest zapisywany w `PROGRESS.md` wraz z mapą scenariuszy oraz jednoznacznym statusem każdego przypadku.
6. Zebrana wiedza trafia do holistycznego skilla i korekty README dopiero po zamknięciu runu oraz spełnieniu jego kryteriów wyjścia.
